2. How the slides design a kernel

  1. Core computation — 3×3 Sobel per pixel.
  2. Independent operation — one output = a chain of dependent instructions (one pixel's gx/gy → mag, bin).
  3. Hardware — latency L, number of units N, SIMD width v: 2 FP units, L = 4, v = 8.
  4. Peak — every unit busy every cycle; busiest unit: 18 FP instructions ÷ 2 units = 9 cycles per 8 pixels ≈ 1.13 cycles/pixel.
  5. Independent instructions needed — L × N = 4 × 2 = 8.
  6. Size the kernel — 2 chains per group → 4 groups (32 pixels); check it fits the registers.
  7. Feed it — data layout and caches (all in L1 for the peak test), then reuse the kernel.

Each cell is one cycle. A chain's next instruction can start only 4 cycles after its previous one. This is the slides' simplified model; the real CPU also overlaps loop iterations, so the current kernel does better than shown (about 83% of its peak in the LLVM model).

4. The same thing as a matrix

The image is a matrix: rows y, columns x. One iteration writes 32 pixels of row y (colored by group) and reads rows y−1, y, y+1 from column x−1 to x+32 (outlined band). Pick a group and a lane to see that pixel's 3×3 window.
